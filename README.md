# Книжный оракул — Netlify + Supabase

Статический сайт на Vite, Supabase Postgres для предложений и метаданных, Supabase Storage для исходных PDF, Supabase Auth для входа администратора. Публичным посетителям не требуется аккаунт. Нет Python-сервера и Netlify Functions.

## 1. Создайте проект Supabase

1. Откройте https://supabase.com/dashboard и создайте проект.
2. В **SQL Editor** выполните весь файл `supabase/schema.sql` **один раз** (повторное выполнение CREATE POLICY вызовет ошибку).
3. В **Authentication → Users** создайте пользователя-администратора с email и паролем (либо пригласите его). Убедитесь, что email подтверждён.
4. Скопируйте UUID этого пользователя. В SQL Editor отдельно выполните:
   ```sql
   insert into public.admin_users (user_id) values ('UUID_АДМИНИСТРАТОРА');
   ```
5. В **Project Settings → API / Connect** скопируйте Project URL и **publishable/anon** key. Никогда не используйте `service_role` или secret key в VITE-переменных.

## 2. Локальный запуск

Нужен Node.js 20+.

```bash
npm install
cp .env.example .env
```

Заполните `.env` значениями `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

```bash
npm run dev
```

Откройте адрес, указанный Vite (обычно http://localhost:5173).

## 3. Публикация на Netlify

1. Загрузите папку проекта в репозиторий GitHub.
2. В https://app.netlify.com выберите **Add new project → Import an existing project**, подключите репозиторий.
3. Build command: `npm run build`; Publish directory: `dist` (уже заданы в `netlify.toml`).
4. В **Site configuration → Environment variables** добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
5. Выполните Deploy. После изменения переменных нужен новый deploy.

## Как пользоваться

На опубликованном сайте читатели выбирают книгу, физическую страницу PDF (первая страница файла = 1) и номер предложения. Администратор нажимает «Администратор», входит по email/паролю и загружает PDF до 20 МБ. Браузер извлекает предложения через PDF.js и загружает исходный PDF в **закрытый** bucket `books`, а предложения — в Postgres. Пока загрузка не завершена, книга скрыта от читателей.

## Ограничения первой версии

- PDF должен иметь текстовый слой; сканы без OCR не поддерживаются.
- Разбиение на предложения эвристическое: сокращения, колонки, переносы, таблицы и диалоги могут приводить к ошибкам. Проверяйте результаты на реальных книгах.
- Обработка идёт в браузере администратора; большие PDF могут требовать много памяти и времени. Лимит 20 МБ установлен в интерфейсе и Storage.
- В случае обрыва соединения в таблице `books` может остаться запись со статусом `processing` или файл в Storage. Администратор может удалить запись через панель; оставшиеся файлы при необходимости удаляются вручную в Supabase.
- Содержимое предложений доступно всем через публичный API, даже если сами PDF закрыты. Загружайте только книги, на распространение текста которых у вас есть права.
- При масштабировании нужны серверная обработка, OCR и модерация/проверка сегментации.

## Безопасность

- Права на запись ограничены политиками RLS и проверкой `admin_users`, а не только интерфейсом.
- Чтение разрешено лишь для готовых книг; доступ к исходным PDF — только администраторам.
- Не включайте открытый signup без необходимости; административные права выдаются только вручную через SQL.
- Используйте сильный пароль и включите MFA для администратора, если доступно.
